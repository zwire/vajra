# Examples

Complete skills generated by vajra. Each `<name>/` is the skill, free of repository values; `<name>.project.md` next to it is the project file one repository would keep at `.flow/<name>/project.md`, with the values of the skill's bindings and the repository facts. Each one is also a test fixture: `npm test` validates it with zero warnings against its project file, checks its `graph.md` is current, runs its eval case, and checks its `scripts/` match the runtime in `skills/vajra/scripts/`.

Read them for calibration: how concrete a domain model, a step and a "Done when" should be. They are not templates to copy into another domain.

| [robot-grasp-flow](robot-grasp-flow/) | ROS 2 pick-and-place, Gazebo first, one real arm | Discovery → flow, hardware | physical-world, stand-in-ladder, data-dependence, measured-outcome | strict | Two areas at different resolution; arm launch guarded behind the operator gate; increment's `writes` leaves the safety limits file out |
| [scrum-team-flow](scrum-team-flow/) | Two-week sprints, QA sign-off, B2B invoicing with a public API | Sprint | shared-contracts, data-mutation | standard | Auto-triggered router; expand-then-contract API changes; release gate with migration dry run |

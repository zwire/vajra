# Principles

Apply these throughout. When a principle changes a decision, name it in your reply.

## Smallest change that works

Write the least code that meets the story's acceptance criteria. Applies to increment, bug-fix and refactor.

## Prove it works

Show evidence from the real artifact (test output, screenshot, CI run), not a claim. Applies to every "Done when".

## Definition of Done is not negotiable

A story is done only when every Definition of Done item holds; unfinished stories return to the backlog instead of shipping partially. Applies to increment and sprint-review.

## Pin behavior before changing it

Capture current behavior in tests before restructuring. Applies to refactor and bug-fix.

## Gate the irreversible

Stop for a human before deploys and data migrations. Applies wherever a step is tagged `[irreversible]`.

## Encode lessons in structure

When something goes wrong twice, change a playbook step or gate instead of adding a reminder. Applies to retro.

# Prototype

## Purpose

Settle a design or experience question by trying alternatives cheaply.

## Steps

1. Name the decision the prototype must make (layout, interaction, API shape, data model, timing behavior).
2. If the design space is open, gather 2–4 references and let the user pick a direction.
3. Build variants with the lightest tools in a scratch location. ⟨parallelism: build N variants in parallel when allowed⟩
4. Put variants side by side or behind one switch.
5. Observe each on the real surface: screenshot, run, time it.

## Done when

- Variants, evidence, tradeoffs and a recommendation are recorded; the prototype is labeled throwaway.
